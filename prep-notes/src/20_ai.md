# B2. AI / Gen AI / Agentic AI / ML Knowledge

> Reading guide: you are interviewing as a product leader, not an ML engineer. For each concept, know (1) what it is, (2) the product decision it changes, (3) how you would measure it, and (4) the risk. Tool and vendor names are examples as of late 2026; names change quickly, so state the capability first and the brand second.

## B2.1 Generative AI and LLMs

> Interview angle: explain LLM behaviour simply, then show you know how to make it reliable in a regulated setting.

- **Generative AI** — Models that produce new content (text, code, images) from learned patterns.
  - PM lens: best fit is language-heavy, review-friendly work: summarising charts, drafting letters, extracting data from documents, answering policy questions. Poor fit alone: decisions needing guaranteed precision.
  - Optum link: chart summarisation (reported 33% less review time), appeal research, member chat assistant (Avery).
- **Large Language Models (LLMs)** — Transformer-based models trained on vast text; they predict the next token. Key concepts: tokens, context window, temperature, system prompts, tool calling, structured outputs.
  - PM lens: unit economics are cost per token, latency and quality. Choose model size per task (small model for classification, larger for reasoning); use routing and caching to control cost.
- **Prompting, fine-tuning and retrieval — choosing the lever** — Prompting is fastest; retrieval adds fresh, private knowledge; fine-tuning shapes style or narrow behaviour.
  - PM lens: start with prompting plus retrieval, add fine-tuning only when evaluation shows a gap that cost or latency justify.
- **Hallucination and grounding** — Models can produce plausible but wrong statements. Grounding ties answers to retrieved sources and requires citations.
  - PM lens: design for "show your source", abstain-when-unsure behaviour and human spot-checks. Track groundedness and citation accuracy.
- **Retrieval Augmented Generation (RAG) / retrieval** — Pattern: split documents into chunks, create embeddings, store in a vector or hybrid index, retrieve relevant chunks at query time, and have the model answer using only those chunks.
  - PM lens: quality depends on chunking, metadata filters (plan year, line of business), hybrid keyword plus semantic search, reranking, freshness and permissions-aware retrieval. Evaluate retrieval separately from generation.
  - Optum link: policy inquiry and benefit inquiry agents are RAG problems with strict version control.
- **Knowledge grounding** — Anchoring AI to authoritative sources (policies, contracts, benefits systems) rather than model memory.
  - PM lens: define the system of record for each answer type and what happens when sources conflict.
- **Conversational AI solutions** — Chat or voice assistants that handle multi-turn tasks.
  - PM lens: metrics include containment (resolved without human), handoff quality, customer satisfaction, average handling time. Always design a graceful escalation.
- **LLM inference** — Running a trained model to produce outputs. Cost and speed depend on model size, hardware, batching and quantisation.
  - PM lens: see B2.5 for platform considerations (GPU capacity, serving frameworks).
- **AI-native products and platforms** — Products whose core value comes from AI, not AI added to an old workflow. Often redesign the workflow and the human role.
  - PM lens: ask "if we started today, would the workflow exist?" Define human-AI task split, feedback loops and data flywheel.
  - Optum link: Optum Real and Optum Integrity One are positioned as AI-first.
- **AI-powered solutions and AI-powered insights** — Predictions, classifications, summaries and recommendations embedded in workflows.
  - PM lens: each insight needs an owner, an action and a measured outcome (uplift versus control).

## B2.2 Agentic AI

> Interview angle: distinguish agents from chatbots and workflows, then explain how you would phase autonomy and measure trust.

- **Agentic AI / agentic platform / agentic products** — Systems where an LLM plans, chooses tools, takes actions and iterates toward a goal with limited step-by-step direction.
  - PM lens: agents add value when tasks are multi-step, variable and tool-dependent. Use deterministic workflows when the path is fixed (cheaper, more reliable). Many good systems are hybrid: workflow skeleton plus agentic steps.
- **Payer Agentic Platform (PAP); payer agents (JD3)** — A shared platform to build, run and govern multiple payer agents (benefit, pricing, policy, prior authorization) with reusable services.
  - PM lens: platform thinking: shared orchestration, retrieval, tool connectors, evaluation harness, guardrails, observability, identity and audit. Each new agent should be faster to launch than the last; that is your platform success metric.
- **Agent orchestration and orchestration frameworks** — Coordination of steps, tools, memory and handoffs. Open-source and vendor frameworks exist (for example LangGraph, Microsoft's agent frameworks, Google's Agent Development Kit, CrewAI, OpenAI Agents SDK), plus cloud-native agent services.
  - PM lens: avoid framework worship. Evaluate on debuggability, state management, observability, security controls, portability and team skills.
- **Multi-agent execution / multi-agent systems** — Several specialised agents cooperating (for example a supervisor routing to worker agents).
  - PM lens: more agents means more failure modes, latency and cost. Justify with measurable gains over a single agent plus tools.
- **Agent runtimes** — The execution environment that hosts agents: sandboxing, scaling, state, secrets, tool access, timeouts, retries.
  - PM lens: this is the product in JD7. Developer-facing outcomes: time-to-first-agent, reliability, cost transparency, secure defaults.
- **Agent lifecycle management** — Build → test/evaluate → approve → deploy → monitor → update → retire.
  - PM lens: version prompts, tools and models together; support canary releases, rollback and deprecation.
- **Agent deployment, execution and scaling** — Hosting, concurrency, queueing for long-running tasks, autoscaling on GPU or API quotas.
  - PM lens: define SLOs for latency and success rate per tier.
- **Tool use and tool/API connectivity** — Agents call APIs, databases and internal systems through defined tools. Emerging standards include the Model Context Protocol (MCP) for connecting models to tools and data, and agent-to-agent protocols for cross-agent communication.
  - PM lens: tool design is product design: clear schemas, least-privilege access, idempotent actions, rate limits, audit logs. Treat each tool as an API product with an owner.
- **Autonomous workflows and decision automation** — Agents completing end-to-end tasks, including decisions.
  - PM lens: define an autonomy ladder: (1) suggest, (2) draft for approval, (3) act on low-risk cases with sampling review, (4) act broadly with exceptions escalated. Set promotion criteria using measured accuracy and error cost. For adverse healthcare decisions keep a clinician in the loop.
  - Optum link: "accelerate approvals, never auto-deny" is the public pattern for InterQual Auth Accelerator.
- **Decision support and workflow automation** — Recommendations plus automated routine steps.
  - PM lens: compare with robotic process automation (RPA): LLM-based steps handle unstructured inputs better but require evaluation.
- **Agent observability** — Traces of prompts, tool calls, outputs, latency, cost and outcomes. OpenTelemetry-style tracing is common.
  - PM lens: you cannot improve what you cannot replay. Require trace storage with PHI controls, dashboards and alerts on quality drift.
- **Interoperability across enterprise systems** — Agents must work with core claims, eligibility, document and case systems.
  - PM lens: integration effort is usually the long pole; prioritise a small set of high-value connectors first.

## B2.3 AI product lifecycle, evaluation and governance

> Interview angle: this is where senior candidates differentiate. Bring a concrete evaluation plan.

- **AI product lifecycle** — Problem framing → data readiness → prototype → evaluation → pilot (shadow mode) → controlled release → scale → monitoring and retraining → retirement.
  - PM lens: new gates compared with classic software: data rights, bias review, evaluation thresholds, human-oversight design, drift monitoring.
- **AI evaluation frameworks and evaluation criteria** — Combine offline tests (golden datasets from real, de-identified cases; edge cases; adversarial prompts), automated scoring (rules, model-as-judge with human calibration) and online metrics (acceptance rate, override rate, outcome quality).
  - PM lens: write evaluation specs before building. Include a regression suite run on every prompt, model or tool change.
- **Quality measures, performance benchmarks and monitoring strategies** — Typical measures: task success, accuracy by segment, groundedness, hallucination rate, escalation rate, latency (p50/p95), cost per task, user satisfaction.
  - PM lens: define thresholds for launch, for expansion and for rollback.
- **Agent accuracy and performance KPIs** — Per-agent measures: correct answer rate, correct tool-call rate, first-contact resolution, containment, time saved.
  - PM lens: report by use case (benefit vs pricing vs policy), not as one blended number.
- **Human-in-the-loop (HITL) systems** — Humans review, correct or approve AI outputs.
  - PM lens: design the reviewer interface (evidence, confidence, quick actions), measure reviewer agreement, and use corrections as training and evaluation data. Beware automation bias: reviewers rubber-stamping.
- **Responsible AI practices; transparency requirements** — Fairness, privacy, safety, accountability, explainability, appropriate use.
  - PM lens: model or system cards, data provenance, intended-use statements, bias testing across demographics where permitted, incident response, user disclosure that AI is involved.
  - Optum link: UHG describes a Responsible AI programme across UnitedHealthcare and Optum; public statements stress clinicians in the loop and no automated denials.
- **AI governance, frameworks and controls** — Approval workflows, risk tiering, model inventory, change control, monitoring, third-party model due diligence. The NIST AI Risk Management Framework is a common reference.
  - PM lens: JD7 notes the platform product integrates with, but does not own, enterprise model approval and policy. Know where your product's responsibility ends and how you consume governance services.
- **Value realisation and value measurement for AI** — Linking AI features to financial and operational outcomes with credible attribution.
  - PM lens: use baselines, holdout groups, and distinguish savings identified from savings realised. Dadlani's public target of about 2:1 return, with many projects paying back in 12–18 months, shows the finance lens Optum applies.
- **Enterprise model approval and access** — Central teams approve which models can touch which data.
  - PM lens: plan lead time for approvals and design for model portability.
- **Validating AI-assisted outputs (JD1)** — Process checks ensuring AI-generated reports are accurate and traceable.
  - PM lens: sampling plans, source links, reviewer sign-off and error logs.

## B2.4 Machine learning and data science

> Interview angle: show you can partner with data scientists, not replace them.

- **Machine learning in healthcare** — Supervised models (classification, regression), unsupervised clustering, NLP, time-series. Healthcare uses: risk stratification, readmission prediction, denial prediction, fraud and anomaly detection, coding suggestion, care-gap identification.
  - PM lens: define the decision, the cost of false positives versus false negatives, and the intervention.
- **Data science collaboration** — Typical flow: problem framing with PM → data exploration → baseline → model → evaluation → deployment with MLOps → monitoring.
  - PM lens: protect data scientists' time by clarifying requirements, labelled data availability and success metrics early.
- **ML model metrics** — Precision, recall, F1, AUC, calibration, lift, fairness metrics.
  - PM lens: pick metrics tied to the business objective (for audit yield: precision at top-K flagged claims, plus recovery per reviewer hour).
- **MLOps and model monitoring** — Versioning, feature stores, CI/CD for models, drift detection, retraining triggers.
  - PM lens: include monitoring and retraining cost in the business case.
- **Production-scale AI solutions** — Moving from prototype to reliable service: scalability, latency, security, support.
  - PM lens: reserve roadmap capacity for hardening, not only features.
- **Sentiment analysis and theme detection (JD1)** — NLP over reviews and surveys to find recurring issues.
  - PM lens: combine with human review for accuracy; track theme trends and link to releases.
- **Data labelling** — Creating labelled examples for training and evaluation.
  - PM lens: budget for expert labelling (coders, nurses) and plan inter-rater agreement.
- **Emerging AI trends and innovative technologies** — Staying current: smaller efficient models, reasoning models, multimodal inputs, computer-use agents, agent interoperability standards.
  - PM lens: have a repeatable way to evaluate new capabilities (time-boxed spikes, evaluation sets) rather than chasing headlines.

## B2.5 AI infrastructure and platforms

> Interview angle: mostly for platform roles such as JD7, but valuable for any Lead TPM. Explain compute, serving and cost in product terms.

- **AI Factory (enterprise AI runtime)** — Optum's internal programme providing secure, scalable runtime and agent platform services across private cloud, public cloud and hybrid environments (JD7).
  - PM lens: treat infrastructure as a product with customers (engineering teams). Metrics: time-to-first-workload, time-to-first-agent, adoption, utilisation, reliability, satisfaction.
- **GPU compute; NVIDIA GPU platforms; GPU-enabled containers** — GPUs accelerate model training and inference. Containers request GPUs through the cluster scheduler.
  - PM lens: scarce and expensive; manage with quotas, scheduling policies, chargeback or showback, and utilisation targets.
- **AI model serving and inference** — Hosting models behind APIs with autoscaling, batching and caching. Common serving stacks include open-source servers and managed endpoints.
  - PM lens: expose service tiers (latency and throughput guarantees), SLOs and clear cost models.
- **Kubernetes and Red Hat OpenShift for AI workloads** — Container orchestration (OpenShift is Red Hat's enterprise Kubernetes). Supports GPU scheduling, multi-tenancy, policy and GitOps.
  - PM lens: you do not need to operate clusters, but should understand namespaces, quotas, upgrades, and the limits of multi-tenancy.
- **AI/ML infrastructure and accelerated compute** — Storage, networking, accelerators.
  - PM lens: capacity planning and demand forecasting with engineering partners.
- **GPU utilisation and capacity efficiency** — Idle GPUs are costly; techniques include bin-packing, sharing, autoscaling and scheduling by priority.
  - PM lens: make efficiency visible with dashboards and set utilisation goals.
- **Enterprise AI platforms: Azure AI Foundry (Azure AI), AWS Bedrock, Google Vertex AI, Databricks** — Managed services for model access, agent building, evaluation, governance and data integration. Azure's offering has been rebranded in recent months (Microsoft Foundry), so name the capability as well as the brand.
  - PM lens: compare on model availability, data residency, private networking, governance integration, cost and lock-in. Multi-cloud portability is a stated goal for AI Factory.
- **Time-to-first-agent and time-to-first-workload** — Developer onboarding speed metrics.
  - PM lens: reduce with self-service portals, templates ("golden paths"), automated approvals and good documentation.

## B2.6 AI-enabled productivity tools and practices

> Interview angle: show you use AI to be a faster, more rigorous PM, and that you check its work.

- **Microsoft 365 Copilot** — AI assistant across Word, Excel, PowerPoint, Outlook and Teams.
  - PM lens: use for first drafts of user stories, acceptance criteria, release notes, test plans and stakeholder updates; you remain accountable for correctness.
- **Teams Copilot** — Meeting summaries, action items, follow-ups.
  - PM lens: use to track decisions and dependencies across India-US time zones; verify action items before circulating.
- **AI-enabled product management tools (Aha!, Rally)** — Aha! offers AI assistance for writing and roadmap content; Rally supports Agile planning and tracking.
  - PM lens: keep tools as the system of record; AI drafts, humans decide.
- **Enterprise-approved AI tools for PM workflows** — Using only sanctioned tools with approved data classifications.
  - PM lens: never paste PHI or confidential data into non-approved tools; mention this explicitly.
- **AI-assisted reporting and automation (JD1)** — Summaries of feedback themes, scorecards, executive narratives.
  - PM lens: document the process, quality checks and traceability so stakeholders trust it.
- **A concrete workflow to cite** — Draft epics from a discovery doc → generate story candidates and acceptance criteria → human edit and add non-functional requirements → generate test scenarios → review against policy and architecture → publish to Aha!/Rally.
  - PM lens: quantify time saved and defects avoided.
